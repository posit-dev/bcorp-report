# Data

Code and data files required for plots in the report.

The plots in `images/generate-plots.qmd` read four output CSVs, each
regenerated by its own script:

| File | Script | Source |
| --- | --- | --- |
| `python_package_downloads.csv` | `get_python_package_downloads.R` | BigQuery PyPI public dataset |
| `r_package_downloads.csv` | `get_r_package_downloads.R` | cranlogs |
| `rstudio_os_downloads.csv` | `get_rstudio_os_downloads.R` | warehouse `desktop-downloads/` + `server-downloads/` (from 2025-06) + internal `downloads.csv` (before 2025-06) |
| `quarto_downloads.csv` | `get_quarto_downloads.R` | GitHub releases + pre-2024 internal `downloads.csv` |

The last two share `read_rstudio_downloads.R`, which reads and classifies the
internal `downloads.csv` feed and also reads the per-month warehouse exports
(`read_warehouse_downloads()`). The Python and R scripts resume incrementally
from the last recorded date in each CSV — re-running appends, it does not
rebuild.

### The RStudio desktop/server sources

Both RStudio Desktop and RStudio Server (open source) downloads come from the
internal `downloads.csv` feed up to 2025-06-01, and from per-month data-warehouse
exports from 2025-06-01 onward (the `downloads.csv` feed stopped updating in early
2026):

- Desktop → `data/desktop-downloads/`, produced by `helpers/desktop_downloads_job.R`
- Server → `data/server-downloads/`, produced by `helpers/rstudio_server_downloads_job.R`

Both jobs run as Posit Workbench jobs and their per-month CSVs are gitignored.
The server job filters to open-source server at query time (Pro / Workbench
editions excluded), so each export folder is a single product and needs no
re-classification.

## Updating the data

1. **Refresh the RStudio download sources** (needed for the RStudio plot):
   - Run `helpers/desktop_downloads_job.R` and `helpers/rstudio_server_downloads_job.R`
     as Posit Workbench jobs to refresh the warehouse exports in
     `data/desktop-downloads/` and `data/server-downloads/`. Both are resumable
     — already-written months are skipped.
   - The internal `downloads.csv` (source for everything before 2025-06) is
     frozen and normally needs no refresh. It is internal tracking data,
     gitignored, and fetched manually; credentials live in `data/.env`
     (gitignored).

2. **Refresh Quarto releases from GitHub** (needs `gh` auth):

   ```bash
   ./helpers/github_quarto.sh   # regenerates releases.csv
   ```

3. **Run the scripts** (needs `bigrquery` auth + billing project
   `pypi-downloads-458318`, and `gh` auth for the r-lib repo list). Each writes
   one output CSV and can be run independently:

   ```bash
   Rscript get_python_package_downloads.R
   Rscript get_r_package_downloads.R
   Rscript get_rstudio_os_downloads.R
   Rscript get_quarto_downloads.R
   ```

   Tip: in `get_python_package_downloads.R`, uncomment the
   `bq_perform_query_dry_run()` line first to check the BigQuery bytes scanned
   before the real query runs.

4. **Re-render** `images/generate-plots.qmd`, then the report (`pbc-report.qmd`).

## Notes

- `downloads.csv` (~755MB) froze in early 2026; the warehouse `desktop-downloads/`
  and `server-downloads/` exports now carry desktop and server downloads forward
  from 2025-06, so the RStudio plot keeps growing (~12% of cumulative added in the
  last 12 months). Server is ~3% of the RStudio total.
- `downloads.csv`'s contribution to Quarto is negligible (~0.1% of total, all
  pre-2024-01-24); the rest of Quarto comes from GitHub releases.
